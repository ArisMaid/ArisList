# STRM 漫画阅读性能优化开发与验收记录

日期：2026-10-03。状态：已实现并完成抽样验证。

## 目标与范围

减少普通 ZIP/CBZ STRM 的开书流量和逐页等待；提前准备接下来 5～10 页；限制原图磁盘缓存并自动淘汰。保留既有来源信任、请求间隔和失败冷却，不以提高云盘并发来换速度。

本次直接覆盖普通 ZIP 漫画页，以及复用同一漫画页接口的图片归档。密码包、分卷包、其他复杂归档的整包准备和音声缓存仍走原有流程，不能把本次 512 MiB 限制理解为所有远程缓存的总限制。标题识别规则不变。

## 问题、原因与实现

| 问题 | 原因 | 已实施方案 | 代码位置 |
|---|---|---|---|
| 开书先传输较大数据 | ZIP 尾部探测曾请求约 64 MiB | 首次仅请求最后 65557 字节，中央目录不在尾部时按偏移补读 | `crates/server/src/strm/archive.rs` |
| 每页额外等待一次请求间隔 | 本地文件头和压缩正文分两次 Range 读取 | 合并一次读取，依据下一条目偏移和文件总长限制范围，再解析实际头长度；验证 206、Content-Range、实际长度 | 同上 |
| 翻页时才开始取图 | 原预加载窗口小，受衍生图开关影响 | 当前页成功后逐张预加载前方 N 页，默认 5、设置范围 5～10，独立于衍生图开关 | `frontend/src/App.tsx`、`frontend/src/api.ts`、`crates/server/src/settings.rs` |
| 原图持续累积 | 原图共用大容量远程缓存，缺少专用小额度 | 普通漫画页放入独立 `cloud-cache/reader-pages/`，容量预留与淘汰在下载前执行 | `crates/server/src/strm/cache.rs`、`crates/server/src/assets.rs` |
| 回翻缓存页被下载任务拖慢 | 缓存读取与冷请求争用执行路径 | 命中原图直接打开本地流，冷请求才进入全局串行准备锁，并在锁内复查缓存 | `crates/server/src/assets.rs` |

合并读取为兼容 ZIP 变长文件名和扩展字段，最多额外覆盖约 128 KiB，且不超过下一条目边界或文件总长。首次开书仍可能需要目录请求；“一次请求”指目录已知后的单个未缓存页面。

## 预加载约定

1. 设置页增加“漫画向前预加载页数”，旧设置自动补默认值 5，后端归一化到 5～10。
2. 当前页加载完成后才启动后台队列；逐张请求，失败停止本轮队列，不自动循环重试。
3. 检测到节省流量或 2G/3G 时暂停后台预加载。浏览器不提供网络信息时按普通网络处理。
4. 翻页、跳页和退出时取消旧窗口后续任务，释放窗口外 Image 引用。已抵达后端的请求可能仍完成，不承诺强制中断上游。
5. 浏览器原生懒加载可能为屏幕内相邻页发起前台请求；后台队列串行不等于浏览器所有请求严格串行。后端冷页准备串行，继续遵守既有远程请求间隔。
6. 前端保留当前页与最多 10 页前向窗口的预加载引用；这不是浏览器自身图片缓存或解码内存的硬配额。

## 原图缓存约定

| 项目 | 实际行为 |
|---|---|
| 默认容量 | 512 MiB；环境变量 `STRM_PAGE_CACHE_MAX_BYTES=536870912`，Compose 已透传 |
| 容量判断 | 下载前按解压后页大小预留，单页不超过 128 MiB 且不超过总额度 |
| 超限淘汰 | 按最后访问时间从旧到新逐个淘汰，尽量降到 75% 额度，默认约 384 MiB |
| 过期 | 24 小时未访问的自有原图，在下一次冷页准备时清理；没有常驻定时清扫线程 |
| 活跃保护 | 最近 60 秒访问的页不参与容量淘汰；命中时更新时间 |
| 无法腾出空间 | 下载前返回 503 和 60 秒重试提示，不继续无限写入 |
| 清理范围 | 只处理独立目录中的普通 `strm-entry-*` 文件，不跟随链接、不递归删除、不操作媒体源 |
| 历史缓存 | 旧 `cloud-cache` 根目录已有原图未迁移、未批量删除，不计入新额度；如需释放旧占用，由用户停服后手动核对清理 |

缓存读取在 Windows 上使用可写文件句柄更新访问时间，避免只读句柄更新时间导致 500。没有引入缓存数据库、后台扫描器或多级调度系统。

## 验证与证据

- 后端 `cargo check`、`cargo build -p media-shelf-server` 通过；前端 `npm --prefix frontend run build` 通过。
- 运行已有 `settings::tests`，8 项通过。没有新增常驻单元/回归测试套件。
- 隔离服务使用生成的 20 页 PNG ZIP 和最大 ZIP 注释：尾部请求 65557 字节，中央目录补读 1080 字节；单页冷读仅一次上游请求，重复读取不再访问上游，图片解码和内容一致性通过。
- 隔离缓存实测覆盖：24 小时过期淘汰、容量淘汰、外部文件保留、近期页面保护、容量不足返回 503 且没有发起下载。证据：`output/strm-speed-check-v2/result.json`。
- 浏览器隔离阅读验证默认 5 页及调整后的 10 页：上游请求分别停在当前页加后方 5 页、10 页，没有把整本 20 页下载完；可见图片解码成功。最终记录共 2 次目录请求和 11 次图片请求：`output/strm-prefetch-ui/requests.json`。
- 真实 8787 服务抽样作品 160：一页 610604 字节 JPEG，1280×1786，冷读取约 1.684 秒，重复读取约 0.018 秒，内容一致。冷/热比较证明缓存收益，不是同条件优化前后测速，不能推导固定提速百分比。

## 使用与后续验收

本地服务已使用新后端代码启动，刷新 5173 页面即可使用新阅读器。先保持默认 5 页；如连续翻页较快，可在设置里调至 10 页。无需重扫全库。

验收时观察正常阅读、快速跳页、退出后重新打开、回翻已读页。若云盘慢于阅读速度，仍可能追上预加载窗口；现阶段先调整阅读窗口及部署网络，不增加云盘并发或全书预下载。实际源的密码包、分卷包和音声性能需另行按其准备流程评估。
